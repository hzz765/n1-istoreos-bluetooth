N1 蓝牙诊断准备包 — 本机准备，未部署

用途与边界
这不是蓝牙修复，也不是可刷镜像。专用 diagnostic.yml 工作流完整编译后制作隔离镜像，不重打包旧内核。
不能把本次内核模块混入当前镜像或原 iStoreOS。日后采用必须从锁定源码完整构建
内核及匹配模块，沿用现有受审 USB 启动、根分区及 eMMC 禁用方案，再复审最终镜像。
HCD、DT 的 UART 流控、GPIO、max-speed 和 eMMC 隔离均保持不变。
目前不要求用户执行此目录中的脚本、重启或刷盘。

证据目标
1. 区分控制器速率命令失败、主机报告速率不符、后续通信异常。
2. 对照故障前后的 UART TX/RX/frame/parity/overrun 等可用软件计数。
3. 用 HCI 时间线记录命令、Command Complete/Status、超时及发现请求。
4. 对照引脚复用、GPIO 软件状态、时钟框架及 runtime PM 状态。
主机报告波特率不是示波器测量；软件 CTS 恒真不能证明实体 CTS 电平。
TX 计数增加只证明驱动处理数据，不证明控制器收到。btmon 无响应也不能单独
区分线路故障和控制器固件挂起。文件结构正确不能排除 HCD 内部逻辑故障。

采集器 collect.sh
先运行现有 n1-bt-check；失败立即退出，不绕过 NBD 或其他隔离检查。
确认 /tmp 是 tmpfs 且至少 64 MiB 空闲；权限0700/0600的私有临时目录。
只读取诊断状态；不执行 scan、power、配对、服务重启、挂载、GPIO或寄存器写入。
btmon 捕获固定120秒，超时结束，并限制各输出文件体积。记录前后快照、每两秒UART计数、退出状态
和校验值。部分日志不可读或文件达到上限会保留失败线索，不能视作采集成功。
不会自动上传或打包工作目录。原始日志可能包含蓝牙地址、设备名称、网络信息及
周围设备广播内容，应私下分析，公开报告只提取必要的脱敏结果。
目前采集只覆盖启动之后的120秒，不能补录已发生的启动期 btmon 数据。
内核中的初始化日志负责补足速率协商信息；后续镜像若需要启动期完整 HCI 捕获，
必须另行设计在 bluetoothd 之前启动的有界采集服务，不能宣称本脚本已覆盖。

后续单次实验设计（尚未授权执行）
先验证最终镜像隔离及日志入口，保持当前HCD及所有硬件参数不变。
将观察、单次触发和结束动作预先整理成一份流程；采集开始后才发出一次发现请求，
避免并发 bluetoothctl 和 btmgmt、重复 scan 或反复重启 bluetoothd 干扰归因。
如果发生第一次超时，保留完整前后日志，不继续 power/scan 重试。
判读应包括：速率命令返回；UART计数差值；HCI最后成功命令和首个未答命令；
是否有串口错误增长；PM/clock变化。基于结果只选择一个有依据的变量调整。
无论成功或失败，先分析采集覆盖和缺失项，不直接要求下一轮刷盘。

复现测试
在项目根目录执行本目录 test_*.py；测试使用本机固定源码/伪设备与模拟命令，
不访问 N1、不读取真实块设备、不验证物理UART，也不等同于ARM内核编译通过。
独立复审结论另见本目录 review.txt（完成后生成）。

工具依赖核对
已只读检查当前基线 root.squashfs：BusyBox 1.36.1-r3，未打包 timeout applet。
未来完整构建必须显式启用 CONFIG_PACKAGE_coreutils-timeout=y，并核对最终根文件系统
中的可执行文件及 GNU timeout --version。当前镜像不能直接照搬本采集器运行。
专用 diagnostic.yml 已加入依赖及 QEMU ARM 程序检查；旧工作流不变。

采集完整性判据与剩余缺口
complete=yes 表示采集窗口、退出状态、前后隔离检查、UART采样及基本snoop头检查通过，
不是蓝牙功能通过，也不表示每个snoop数据帧均已解析、无丢包或故障原因已确定。
必须保留诊断内核的初始化及速率结果标记；读取失败、标记丢失或HCD校验不符均拒绝
报告完整。若初始化本身失败导致后续标记不存在，已有日志仍应保留用于分析。
尚未在目标 BusyBox ash + GNU timeout + 真实 btmon 上验证进程终止行为；本机测试
使用模拟工具。采集器目前没有启动期HCI全量抓包、物理CTS电平或线缆波形记录。
如UART统计不可用会标记不完整，不会用伪造的CTS状态替代实测。
部署前还需要完整ARM目标编译、最终镜像检查及目标工具验证。本轮只允许云构建和镜像检查，未授权部署。
